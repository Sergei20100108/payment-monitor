# PaymentMonitor — мониторинг статусов платежей по выпискам Excel

Windows-приложение (WinForms, **C# / .NET Framework 4.7.2**), которое читает банковские
выписки в формате **xlsx**, складывает платежи в локальную базу **SQLite** и показывает
смену статусов. Есть визуальный интерфейс и консольный режим для автоматизации.

> **Только начали?** Пошаговая инструкция «как пользоваться» — в [Справка.md](Справка.md).
> Здесь — техническое описание и детали реализации.

## Что умеет

- **Импорт файла выписки** (кнопка «Импорт файла…», можно выбрать сразу несколько файлов).
- **Мониторинг папки**: раз в N секунд проверяет папку и автоматически импортирует новые `*.xlsx`.
- **Автоопределение колонок**: шапка ищется в первых 15 строках, колонки распознаются по
  ключевым словам (`Сумма`, `Дата…`, `Номер…`, `Статус`/`Состояние…`, `Контрагент`, `Назначение…`,
  `Валюта`). Один столбец используется только одним полем: если в шапке есть и «Сумма в валюте счёта»,
  и «Код валюты», сумма берётся из первого, а валюта — из второго.
- **Нормализация статусов**: «Исполнено», «Проведено», «Завершено», «Успешно» (`SUCCESS`) → `succeeded`;
  «Отклонено», «Ошибка» → `failed`; «Возврат», «Сторно» → `refunded`; «Отменено», «Отозвано» → `canceled`
  и т.д. Незнакомые формулировки сохраняются как есть и дают статус `unknown`.
- **История изменений**: каждое изменение статуса пишется в `payment_events` (видно, из какого
  файла и когда пришло изменение).
- **Идемпотентность**: повторный импорт того же файла (совпал SHA-256) пропускается;
  повторный импорт изменённой выписки обновляет только реально изменившиеся записи.
- **Правка выписки**: встроенный редактор (кнопка «Редактор выписки…») открывает `xlsx`, показывает
  таблицу и позволяет менять данные, сохраняя их обратно в файл. Сразу после сохранения выписка
  импортируется — удобно проверять, как программа ловит смену статусов.
- **Фильтры и поиск** в интерфейсе: по статусу и по номеру/контрагенту/назначению.
- **Журнал импортов** (`import_runs`) и лог событий в окне.

## Требования

- Windows 7 SP1 / 10 / 11.
- .NET Framework 4.7.2 (в Windows 10/11 уже входит).
- Для сборки: Visual Studio 2019+ **или** .NET SDK (`dotnet build`).
- NuGet-пакеты (подтягиваются автоматически):
  - `EPPlus` 4.x — чтение xlsx без установленного Excel (лицензия MIT);
  - `System.Data.SQLite.Core` — локальная база.

## Сборка и запуск

Через консоль (из корня `payment-monitor`):

```powershell
dotnet build src\PaymentMonitor\PaymentMonitor.csproj -c Release
.\src\PaymentMonitor\bin\Release\PaymentMonitor.exe
```

Через Visual Studio: откройте `PaymentMonitor.sln` → проект **PaymentMonitor** → F5.

## Интерфейс

| Элемент | Назначение |
|---|---|
| **Импорт файла…** | выбрать один или несколько `xlsx` и загрузить |
| **Редактор выписки…** | открыть выписку и изменить данные в ней (статус, сумма, дата и т.д.) |
| **Папка + Обзор…** | папка, за которой следит мониторинг |
| **▶ Мониторинг: выкл / ⏹ вкл** | включить/выключить периодический обход папки |
| **Интервал, сек** | период обхода (по умолчанию 60) |
| **Банк** | имя банка — разделяет платежи из выписок разных банков |
| **Статус / Поиск** | фильтр и поиск по таблице |
| **Таблица платежей** | дата, сумма, статус (цветом), номер, контрагент, назначение, когда обновлён |
| **История изменений** | по выбранному платежу: было → стало, из какого файла |
| **Журнал событий** | что происходит в реальном времени |

У окна своя рамка: в правом верхнем углу шапки — круглые кнопки **свернуть**, **развернуть/восстановить**
и **закрыть** (у «закрыть» кружок краснеет под курсором). Окно перетаскивается мышью за шапку,
разворачивается двойным щелчком по ней и тянется мышью за край рамки.

Двойной клик по ячейке «Назначение» — текст целиком в подсказке (наведите мышь).

По правому клику на платеже — «**Открыть выписку в редакторе…**» (файл ищется в папке
мониторинга по имени, из которого платёж был загружен).

## Правка выписки (редактор)

Кнопка **«Редактор выписки…»** открывает `xlsx` прямо в программе — Excel не нужен:

- сверху выбирается **лист**, если в файле их несколько;
- правятся только **распознанные колонки** (Дата, Сумма, Статус, Назначение, Валюта, Контрагент,
  Номер) — служебная «шапка» банка и прочие колонки заблокированы и показаны серым;
- в колонке «Статус» при вводе подсказываются формулировки (Исполнено, В обработке, Отклонено…),
  а ячейки статуса подсвечиваются тем же цветом, что и в таблице платежей;
- **➕ Добавить строку** — новый платёж сразу после последнего (оформление копируется);
- **➖ Удалить строку** — удалить строку из файла (итоговые строки сдвинутся вверх);
- **💾 Сохранить в файл** — записать изменения в исходный `xlsx`.

Сразу после сохранения файл импортируется в базу, поэтому смена статуса тут же появляется
в таблице платежей и в «Истории изменений» (например: `В обработке → Отменено`).

Тот же редактор открывается, если **перетащить `xlsx` на значок программы** (или выбрать
программу через «Открыть с помощью»):

```
PaymentMonitor.exe "C:\Выписки\выписка.xlsx"
```

Если выписка открыта в Excel, сохранить не получится — программа скажет об этом: закройте файл
в Excel и повторите.

> Удаление строки убирает её из файла, но **уже загруженный в базу платёж не удаляется**:
> база — это журнал. Чтобы очистить всё, см. раздел «Файлы приложения».

## Консольный режим (для задач по расписанию)

```
PaymentMonitor.exe --import "C:\Выписки\выписка.xlsx" [--bank "Сбер"] [--force]
PaymentMonitor.exe --scan   "C:\Выписки"              [--bank "Сбер"]
PaymentMonitor.exe --list   [--status succeeded] [--search ромашка] [--limit 50]
PaymentMonitor.exe --runs

PaymentMonitor.exe --edit "C:\Выписки\выписка.xlsx"                     [--sheet Имя]
PaymentMonitor.exe --edit "C:\Выписки\выписка.xlsx" --row 11 --set status=Отменено --save
PaymentMonitor.exe --edit "C:\Выписки\выписка.xlsx" --add-row --set external_id=ПП-9999 --save
PaymentMonitor.exe --edit "C:\Выписки\выписка.xlsx" --delete-row 18 --save
```

- `--edit` без `--save` только **показывает** таблицу выписки; `--set поле=значение` (можно
  несколько раз) меняет данные указанной строки `--row`; имена полей: `date`, `amount`, `status`,
  `purpose`, `currency`, `counterparty`, `external_id` (или номер колонки).

- `--force` — импортировать повторно, даже если файл уже был загружен (после правки маппинга).
- Отчёт пишется и в консоль, и в файл `logs\last-run.txt`.
- Пример задачи в Планировщике Windows (ежедневно в 9:00):

```powershell
schtasks /Create /TN "PaymentMonitor scan" /SC DAILY /ST 09:00 ^
  /TR "\"C:\PaymentMonitor\PaymentMonitor.exe\" --scan \"C:\Выписки\""
```

## Как определяется «тот же платёж»

Ключ строки `row_key`:

1. если есть номер документа — `ext:<номер>`;
2. если номера нет — отпечаток `fp:<sha256(дата|сумма|контрагент|назначение)>`.

Поэтому устройство простое и предсказуемое: **номер документа — главный идентификатор**,
а выписка без номеров сопоставляется по совпадению реквизитов.

Особенность: «пустые/неизвестные» статусы (`new`, `unknown`) **не затирают** уже известный
статус (например, `succeeded` не превратится в `unknown`, если банк прислал непонятное значение —
сырое значение просто сохранится в `raw_status`).

## Порядок работы (рекомендуемый)

1. Загрузите одну выписку кнопкой «Импорт файла…» и убедитесь, что колонки распознались.
2. Если колонки не распознались — пришлите мне файл (можно обезличенный), добавим ключевые слова
   в `Core/Parsing.cs` (словарь `FieldKeywords`) или маппинг статусов (`StatusRules`).
3. Укажите папку выписок и включите мониторинг — новые выгрузки будут подхватываться сами.

## Файлы приложения

| Файл | Что это |
|---|---|
| `payments.db` | база SQLite (создаётся рядом с exe) |
| `settings.xml` | настройки: банк, папка, интервал |
| `logs\crash.txt` | трассировка, если приложение упало |
| `logs\last-run.txt` | отчёт последнего консольного запуска |

Сброс данных: удалите `payments.db*` при закрытом приложении.
Если папка с exe недоступна для записи, база и настройки уйдут в `%APPDATA%\PaymentMonitor`.

## Ограничения и заметки

- Поддерживаются только `*.xlsx` / `*.xlsm`. Старые `*.xls` — сохраните как `.xlsx`.
- Если файл открыт в Excel, чтение обычно проходит; временные файлы `~$…` игнорируются.
- Редактор пишет изменения в тот же файл: если выписка открыта в Excel, сохранение не пройдёт —
  программа попросит закрыть файл.
- Суммы разбираются в копейках: `15 000,00`, `15000.00`, `1.234,56`, `(5 000,00)` (скобки = минус).
- Даты: `дд.мм.гггг`, дата Excel, `гггг-мм-дд`.
- Поиск регистронезависимый (в т.ч. по кириллице).

## Тестовые данные

Готовый **пример банковской выписки**: `fixtures\Пример_выписки_банка.xlsx` —
12 платежей, «шапка» банка (БИК, р/с, период, остаток), два листа, строки «Итого оборотов»
и «Остаток на конец периода» (программа их пропускает).

**Шесть выписок в разных «банковских» стилях** — в `fixtures\примеры\`
(статусы латиницей, колонка «Состояние документа», выписка без валюты, без номера документа,
повторная выгрузка со сменой статусов). Подробное описание и ожидаемые цифры —
в [fixtures/примеры/README.md](fixtures/примеры/README.md).

```powershell
# пересоздать примеры и демо-выписки (нужен python + openpyxl)
python fixtures\make_example_statement.py
python fixtures\make_fixture.py
python fixtures\make_bank_examples.py

# попробовать на примере
PaymentMonitor.exe --import "fixtures\Пример_выписки_банка.xlsx"
PaymentMonitor.exe --list

# все шесть примеров разом (файл 06 изменит статусы из файла 01)
PaymentMonitor.exe --scan "fixtures\примеры"
PaymentMonitor.exe --list --limit 50

# демонстрация смены статусов между выгрузками
PaymentMonitor.exe --import fixtures\выписка_1.xlsx   # создаст 4 платежа
PaymentMonitor.exe --import fixtures\выписка_2.xlsx   # +1 новый, 2 статуса изменились
```
