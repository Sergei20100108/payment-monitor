# Краткая справка — PaymentMonitor

Как пользоваться программой. Подробности — в [README.md](README.md).

---

## 1. Первый запуск

1. Запустите `PaymentMonitor.exe` (окно откроется сразу, ничего настраивать не нужно).
2. В поле **«Банк»** впишите название банка — это нужно, чтобы платежи из выписок разных банков
   не смешивались (например, `Сбербанк`).
3. Нажмите **«Импорт файла…»**, выберите выписку `*.xlsx` — платежи появятся в таблице.

База создаётся сама рядом с программой (`payments.db`). Ничего устанавливать не требуется.

## 2. Чтобы новые выписки подхватывались сами

1. Нажмите **«Обзор…»** и выберите папку, куда вы (или 1С/банк) складываете выписки.
2. Нажмите **«▶ Мониторинг: выкл»** — кнопка станет **«⏹ Мониторинг: вкл»**.
3. Всё, что появится в этой папке, будет загружаться автоматически (по умолчанию раз в 60 секунд,
   интервал меняется полем **«Интервал, сек»**).

Повторно один и тот же файл не загрузится — программа сравнивает отпечаток файла.
Если выписка обновилась (изменились статусы), просто положите новую версию — статусы обновятся,
а дубликаты не появятся.

## 3. Что где в окне

| Элемент | Зачем |
|---|---|
| **Импорт файла…** | загрузить выписку вручную (можно сразу несколько файлов) |
| **Редактор выписки…** | открыть выписку и изменить в ней данные (статус, сумму, дату…) |
| **Папка / Обзор…** | папка для автоматического мониторинга |
| **▶ Мониторинг** | включить/выключить автоматическую загрузку |
| **Интервал, сек** | как часто проверять папку |
| **Банк** | название банка (разделяет выписки разных банков) |
| **Статус / Поиск** | отфильтровать таблицу; искать можно по номеру, контрагенту, назначению |
| **Таблица платежей** | дата, сумма, статус, номер, контрагент, назначение, когда обновлён |
| **История изменений** | по выбранному платежу: что было → что стало и из какого файла |
| **Журнал событий** | что делает программа прямо сейчас |
| **Строка внизу** | сколько всего платежей и по каким статусам, путь к базе |

Полный текст назначения платежа — наведите мышь на ячейку (появится подсказка).

## 4. Статусы

| В выписке банка | В программе | Цвет |
|---|---|---|
| Исполнено, Проведено, Оплачено, Зачислено, Завершено, Успешно (SUCCESS) | **Исполнен** | зелёный |
| В обработке, Ожидает, На проверке | **В обработке** | оранжевый |
| Отклонено, Отказ, Ошибка, Не проведено, Неуспешно | **Отклонён** | красный |
| Отменено, Отозвано (CANCELED) | **Отменён** | серый |
| Возврат, Сторно (REFUND) | **Возврат** | фиолетовый |
| Новый, Создан | **Новый** | синий |
| что-то незнакомое | **Неизвестен** | жёлтый |

Важно: «пустой» статус (Неизвестен/Новый) **не затирает** уже известный. Если банк однажды прислал
«Исполнено», а позже — непонятное значение, статус останется «Исполнен», а сырой текст банка
сохранится в базе.

## 5. Как программа понимает, что это «тот же» платёж

1. По **номеру документа** (например, `ПП-1024`) — это главный признак;
2. Если номера нет — по совокупности: дата + сумма + контрагент + назначение.

Поэтому в одной выписке платёж должен иметь номер документа, либо совпадать по реквизитам.

## 6. Где хранятся данные

| Файл | Что это |
|---|---|
| `payments.db` | вся база: платежи, история, журнал импортов |
| `settings.xml` | ваши настройки (банк, папка, интервал) |
| `logs\last-run.txt` | отчёт последнего запуска из консоли |
| `logs\crash.txt` | появится, только если программа упала |

**Начать с чистого листа:** закройте программу и удалите файл `payments.db`
(и, если есть, `payments.db-wal`, `payments.db-shm`). Настройки при этом сохранятся.

## 7. Консольный режим (для автоматизации)

Можно запускать без окна — например, по расписанию в Планировщике задач Windows:

```powershell
PaymentMonitor.exe --import "C:\Выписки\выписка.xlsx"   # загрузить один файл
PaymentMonitor.exe --scan   "C:\Выписки"                # загрузить все новые файлы из папки
PaymentMonitor.exe --list                               # показать платежи
PaymentMonitor.exe --list --status succeeded            # только исполненные
PaymentMonitor.exe --list --search ромашка              # поиск
PaymentMonitor.exe --runs                               # журнал импортов

PaymentMonitor.exe --edit "C:\Выписки\выписка.xlsx"     # показать таблицу выписки
PaymentMonitor.exe --edit "C:\Выписки\выписка.xlsx" --row 11 --set status=Отменено --save
```

Дополнительно:

- `--bank "Сбербанк"` — указать банк;
- `--force` — загрузить файл повторно, даже если он уже был загружен (нужно после правки настроек
  распознавания, чтобы перечитать выписку);
- отчёт всегда дублируется в файл `logs\last-run.txt`.

## 8. Если что-то не так

| Симптом | Что делать |
|---|---|
| «Не найдена шапка таблицы» | проверьте, что в файле есть колонка **«Сумма»** и ещё хотя бы одна (Дата/Номер/Статус/Состояние). Если названия нестандартные — пришлите файл разработчику, добавим ключевые слова |
| Колонки определились неверно | то же: нужно добавить/уточнить названия колонок в программе. Статус понимается и как «Статус», и как «Состояние документа» |
| Статус «Неизвестен» | банк прислал формулировку, которой нет в правилах — она сохранена целиком, можно добавить правило |
| Файл не читается | поддерживаются только `*.xlsx` / `*.xlsm`. Старый `*.xls` откройте в Excel и сохраните как «Книга Excel (*.xlsx)» |
| В таблице 500 записей | это ограничение вывода: уточните фильтр по статусу или поиск |
| Файл открыт в Excel | обычно всё равно читается; временные файлы `~$…` игнорируются |
| «Не удалось сохранить файл» в редакторе | выписка открыта в Excel — закройте файл и сохраните снова |

## 9. Сборка из исходников (если нужно пересобрать)

**Visual Studio 2019+:** откройте `PaymentMonitor.sln` → **F5**.

**Командная строка:**

```powershell
git pull
dotnet build PaymentMonitor.sln -c Release
.\src\PaymentMonitor\bin\Release\PaymentMonitor.exe
```

Первая сборка скачает NuGet-пакеты (нужен интернет). Готовый exe можно скопировать в любую папку
и запускать там — база создастся рядом с ним.

## 10. Проверить на примере

В папке `fixtures\` лежит готовая выписка `Пример_выписки_банка.xlsx` (12 платежей).
Загрузите её кнопкой «Импорт файла…» — увидите, как программа разбирает реальную структуру
выписки: «шапку» банка, служебные строки «Итого оборотов», разные статусы.

Рядом, в `fixtures\примеры\`, — **шесть выписок в разных банковских стилях** (статусы латиницей,
колонка «Состояние документа», без валюты, без номера документа, повторная выгрузка со сменой
статусов). Достаточно указать эту папку для мониторинга или выполнить:

```powershell
PaymentMonitor.exe --scan "fixtures\примеры"
```

Файл `06_повторная_выгрузка_смена_статусов.xlsx` меняет статусы платежей из файла `01` — после
загрузки откройте по ним «Историю изменений». Подробности и ожидаемые цифры — в
`fixtures\примеры\README.md`.

## 11. Как изменить данные в самой выписке

Иногда нужно поправить выписку: например, проверить, как программа отреагирует на смену статуса.
Для этого в окне есть кнопка **«Редактор выписки…»** — Excel не нужен.

1. Нажмите **«Редактор выписки…»** и выберите файл `xlsx` (или просто **перетащите файл на значок
   программы**).
2. В открывшемся окне — таблица выписки. Менять можно колонки **Дата, Сумма, Статус, Назначение,
   Валюта, Контрагент, Номер**; остальные (служебная «шапка» банка) заблокированы и показаны серым.
   - в колонке «Статус» при вводе подсказываются формулировки — начните печатать и выберите из списка;
   - **➕ Добавить строку** — новый платёж сразу после последнего;
   - **➖ Удалить строку** — удалить строку из файла (итоговые строки сдвинутся вверх);
   - **💾 Сохранить в файл** — записать изменения (пока не нажали — файл не меняется).
3. После сохранения выписка **сразу загружается в базу**: изменённый статус появится в таблице
   платежей и в «Истории изменений» (например: `В обработке → Отменено`).

Полезно для проверки: откройте выписку, поменяйте статус платежа на «Отменено», сохраните — и в
истории изменений появится новая запись.

Если файл открыт в Excel, сохранить не получится — программа попросит закрыть файл.
